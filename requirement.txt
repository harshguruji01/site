Here is the list of files, URLs, and APIs in the frontend that currently point to the old Google Apps Script backend and need to be updated to point to the new Node.js backend, along with the required changes.

### 1. `js/script.js` (or root `script.js`)
Currently uses `GS_ENDPOINT` for authentication and content fetching.
- **Variable to Update:**
  - Line ~920: `const GS_ENDPOINT = window.GS_ENDPOINT || 'https://YOUR_GAS_WEBAPP_URL';`
  - **New URL:** Should point to `https://api.webguruji.online/api` or `http://localhost:5000/api` for local development.

- **API Changes required in `script.js` / frontend forms:**
  - `?action=register` -> **Update to:** `POST /api/auth/signup`
  - `?action=login` -> **Update to:** `POST /api/auth/login`
  - `?action=saveAutoLogin` -> **Update to:** (May not be needed if using HTTP-only cookies, but can map to `GET /api/auth/me` or similar session check)
  - `?action=verifyAutoLogin` -> **Update to:** `GET /api/auth/me`
  - `?action=sendOtp` -> **Update to:** `POST /api/auth/forgot-password`
  - `?action=verifyOtp` -> **Update to:** `POST /api/auth/verify-email` (or a dedicated OTP verification route)
  - `?action=resetPassword` -> **Update to:** `POST /api/auth/reset-password`
  - `?action=getDailyContent` -> **Update to:** `GET /api/content/daily` (Need to implement this in the backend to maintain existing frontend behavior)

### 2. `login.js` and `signup.js` (if they have API calls)
- Ensure any `fetch()` calls in these files (if they exist instead of `script.js`) are updated to the new REST API structure (`/api/auth/...`) instead of the `GS_ENDPOINT` query parameters.

### 3. Google OAuth Integration (New Requirement)
- Frontend will need a new "Login with Google" button pointing to `GET /api/auth/google`.
- The frontend will handle the redirection back from the backend upon successful OAuth.

### 4. Admin Panel (`admin.html`, `admin_store.html`, etc.)
- Existing admin pages will need JavaScript written to call the new `/api/admin/*` endpoints.
- Must include credential inclusion (`credentials: 'include'`) in fetch requests to send HTTP-only session cookies.

### 5. Profile / User Area
- Pages like `profile.html`, `settings.html`, `dashboard.html` need to fetch data from `GET /api/users/me` and update data via `PATCH /api/users/me`.

**Note:** As per instructions, the frontend files WILL NOT be modified directly by this backend task unless explicitly instructed later. This document serves as the requirement tracking for frontend integration.
